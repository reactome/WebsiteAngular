# Contract: the module and the description

## `projects/contract/`

```text
projects/contract/
├── package.json        # {"type":"module"}
├── README.md           # what belongs here, the rules below
├── scalars.ts          # Long, EpochMillis, Highlighted
├── search.ts           # SearchEntry and its kinds, projections, results, facets, icons
├── routes.ts           # the route table: method, route, answer type (types only)
├── openapi.json        # generated; committed; checked up to date
└── <family>.ts         # later families, one module each (content, schema, interactors, …)
```

**Rules** (enforced by the checks in [checks.md](checks.md)):

- **Types only.** The modules hold `export type` and `export interface`, and nothing that emits code: no enum, namespace, constant or class.
- **Imports.** A contract module imports only other contract modules, with `import type` and a relative path ending in `.ts`.
- **Named type arguments.** Every type argument in an answer type is a named type, so the description's names are stable.
- **One `@discriminator`.** A union with a single marker field (graph objects: `schemaClass` or `className`) carries the `@discriminator` tag. The search entry has none (see research R4).
- **Writer helpers stay with the service.** `JsonWritten`, `compact`, `nonEmptyJson` and `JsonMember` remain in `tools/content-node/answers.ts` and take contract types as arguments.

**Who imports it**:

- **The service.** `tools/content-node` modules import it with `import type` from `../../projects/contract/<module>.ts`.
- **The site and the pathway browser.** Their model files re-export the contract's types under the names their readers already use, then the readers move to the contract's names as they are touched.
- **The recorded-answer check.** `tools/api-types/calls.ts`'s `TYPES` imports from the contract as types move.

## The description: `projects/contract/openapi.json`

- **The format.** It is OpenAPI 3.1.1, generated by a script under `tools/` (TypeScript, spec 013) with ts-json-schema-generator 2.9.0 (`discriminatorType: 'open-api'`, `skipTypeCheck: true`, since the type checks already ran).
- **`components.schemas`.** These are the generator's definitions for the answer types the route table names, with refs rewritten from `#/definitions/` to `#/components/schemas/`.
- **`paths`.** There is one per route in the route table: its method, and a `200` response with the answer type's `$ref`. A route the service serves that is not yet in the contract is listed with the extension `x-contract: "not yet"` and no response schema, so nothing presents an unchecked generic object as checked.
- **What it does not hold.** Parameters stay in Java's `tools/content-node/openapi-snapshot.json` (spec 011's cache labelling) until a later task merges them in. The site's API page keeps reading Java's live description until the service publishes this one.
- **When it is regenerated.** It is regenerated in the same change as any contract change; the up-to-date check fails otherwise.
