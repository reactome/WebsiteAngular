# Contract: the checks

Each check is shown failing before it is trusted (constitution III). The deliberate breakage used to show it is named below.

| Check                                                       | Where (planned)                                                                   | Holds                                                                                                  | Shown failing by                                                                                   |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Both sides compile                                          | `npm run check:types` (site), `tools/tsconfig.json` (service)                     | A contract type renamed or retyped fails the writer and every reader                                   | Renaming a field of a moved type: the service module and the site and pathway browser readers fail |
| The contract is types only                                  | a boundary spec under `projects/contract/`                                        | The contract imports nothing outside itself, and declares no value                                     | Adding `export const` or an import from `projects/website-angular` to a contract file              |
| Service imports leaving `tools/content-node/` are type-only | the same boundary spec (syntax tree, not `preProcessFile`)                        | No value import reaches outside the image's copy of `tools/content-node/`                              | Changing one `import type` from `projects/` to `import`                                            |
| No second description                                       | a spec listing the readers' re-exports                                            | A moved answer is not also declared in `projects/website-angular/src/model` or the pathway browser     | Re-adding a local `interface SearchEntry`                                                          |
| Recorded answers (compile)                                  | `tools/api-types` (spec 012), `TYPES` pointing at the contract                    | Known problems per route and type never rise                                                           | Marking a field required in a kind whose recorded entries lack it                                  |
| Recorded answers (schema)                                   | a spec under `tools/api-types` running ajv 2020-12 on the generated description   | Every recorded answer of a contract route matches; the search entry matches exactly one kind (`oneOf`) | Removing one kind: its entries match none. Making two kinds overlap: their entries match two       |
| Description up to date                                      | a spec regenerating `projects/contract/openapi.json` in memory                    | The committed description equals what the contract generates                                           | Changing a contract field without regenerating                                                     |
| Route table complete                                        | a spec comparing the contract's route table with `tools/content-node/registry.ts` | Every contract route is served, and every served route is in the contract or listed as not yet         | Adding a table row for a route the registry lacks                                                  |
| Entity types complete                                       | a spec reading the domain snapshot                                                | The entity kind's `type` list covers every class the indexer's mapping passes through                  | Removing one class from the list                                                                   |
| Answers unchanged                                           | the parity comparison, the e2e suite, before and after on beta                    | Every search answer is byte-identical                                                                  | (the existing checks; each PR records its before/after)                                            |

**Counts that may only fall**: the known problems (`tools/api-types/known-problems.json`), lint warnings, dead code and the services' loose values.
