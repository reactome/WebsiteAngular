# Contract: `deploy/graphdb/graph.sh`

Run with sudo from an up-to-date checkout of the repository: `sudo bash deploy/graphdb/graph.sh <subcommand> [args]`.

## What every subcommand does

- **Settings** come from `steps.env` in the state folder (default `/var/lib/reactome-graphdb`): the data folder, the
  credentials file and the compose project directory as absolute paths, the services' release URLs, the command
  that restarts Tomcat, and the image name, Bolt port and compose project name (defaults `reactome-graphdb`, 7687 and
  the stack's own project; a test copy sets its own, so it never meets the serving graph's port or image). Never from `~` or the caller's environment, which sudo changes (research R9).
- **One at a time:** all but `status` take an exclusive `flock` on the state folder for the whole run; a second step
  is refused at once (exit 2).
- **Pending configuration** (FR-010): each prints first whether the applied configuration differs from `graph.json`
  in this checkout, and the commit it reads; the checkout must be pulled first.
- **Interrupted steps:** all but `status` refuse while `state.json` records another step, except that step's own
  rollback or a re-run of it.
- **Before each change** to the data folder or the applied configuration, `state.json` is written (FR-010a).
- **Copies only with Neo4j stopped**; `cp -a`, so owners and modes are kept. A store put in place is given the data
  folder's owner (it usually arrives owned by root).
- **Login check** (FR-005): the credentials file's user and password must log in, or the step stops before any
  change (and, after a start, rolls back).
- **The password** is read with the wrapper's literal parser and passed to `cypher-shell` only in the container's
  environment (`docker exec -e`), never on a command line.
- **Stops are graceful:** `docker stop -t 120` (and `stop_grace_period: 120s` in compose), so a large page cache is
  flushed.
- **A log** of every action, check and container log (captured before a `--rm` run is stopped) goes to
  `logs/<time>-<subcommand>.log` in the state folder; its path is the last line printed.
- **Room:** free space must cover what the step will write (copies, stores, an image build) plus 2 GB; the previous
  data copy is removed first when the serving state no longer needs it. Otherwise refused before any change.
- **Rollbacks in order:** `history.json` records each completed step; a rollback is allowed only for the last one
  (`rollback-apply` after a later `release` is refused, since its copy predates that release).

## Queries made (FR-013)

On the graph: the login, the release number, the three label counts (count store). On the system database, not the
graph: `SHOW DATABASE graph.db` (online or not), `dbms.components()` and `dbms.upgradeStatus()`, which read Neo4j's
own state. Each service's release answer, through the service.

## Output

One line per action and check, `==` for a stage and two spaces for a detail; the last lines say what serves, what to
do next, and where the log is. Nothing prints the password.
