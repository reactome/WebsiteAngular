# Contract: `deploy/graphdb/graph.sh`

Run with sudo from the repository's root: `sudo bash deploy/graphdb/graph.sh <subcommand> [args]`. Every
subcommand but `status` refuses without root, refuses while another step is recorded under way (unless it is that
step's own rollback or a re-run of it), and writes `state.json` before each change it makes.

| Subcommand         | Does                                                                                                                                                                                                                                                                                                                                                                                                                         | Exit                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `status`           | Applied vs repository configuration (equal, or pending and the step that applies it); a step under way and how to finish or undo it; the graph's database status and release; each service's release; one Neo4j on the port. Read-only.                                                                                                                                                                                      | 0 consistent; 1 anything to act on                             |
| `release <folder>` | Room check; counts from the serving database; stop the graph; set aside `graph.db` and its logs; move the new store in; one allowance run (missing logs, and store upgrade if the store is older within the major); standing start; checks (online, release number, counts ≥ 90% of the previous unless `--shrink-expected`); restart content-node, Tomcat, java-library and check each. On any failure, `rollback-release`. | 0; 1 rolled back, with the reason; 2 refused before any change |
| `rollback-release` | Put the set-aside database back (an older store opened as `release` opens one), restart the services, check each answers the previous release. If that fails too, stop and report, leaving it serving.                                                                                                                                                                                                                       | 0; 1                                                           |
| `apply`            | Build the image from `graph.json` (base by digest, plugins by sha256); refuse another major; room check; data copy; tag `:previous`, `:applied`; if the version changed, one run with store upgrade allowed; standing start; checks (`dbms.components`, `dbms.upgradeStatus`, release); restart and check the services. On failure, `rollback-apply`.                                                                        | 0; 1 rolled back; 2 refused                                    |
| `rollback-apply`   | Restore the data copy and `:previous` as `:applied`; start; check; restart and check the services.                                                                                                                                                                                                                                                                                                                           | 0; 1                                                           |
| `cutover`          | The first apply from the host installation: the image must be the store's version (FR-002a); data copy; stop and disable the host service; start the container as the folder's owner; checks; services. On failure, `rollback-cutover`.                                                                                                                                                                                      | 0; 1; 2                                                        |
| `rollback-cutover` | While the package is installed: stop the container, enable and start the host service, check, services.                                                                                                                                                                                                                                                                                                                      | 0; 1; 2 if the package is gone                                 |
| `retire`           | With the container serving and checked: disable the host service, remove the package (not purge), keep the data folder; the cut-over rollback ends here.                                                                                                                                                                                                                                                                     | 0; 2                                                           |

Output: one line per action and check, prefixed `==` for a stage and `  ` for a detail; the last line says what
serves and what to do next. Nothing prints the password.
